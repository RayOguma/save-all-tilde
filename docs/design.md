## 2. 画面デザイン

### 2.1 レイアウト

```
┌──────────────────────┬────────────────────────────────────────┐
│ 🗺 マップ             │  ユウ@チルダ村:~/村はずれ$ ls              │
│                      │  看板  立入禁止/  柵の裏/                  │
│ チルダ村              │  ユウ@チルダ村:~/村はずれ$ cd 立入禁止      │
│ ├ 掲示板             │  cd: 立入禁止: Permission denied          │
│ ├ チョウン爺の家      │  （扉には重い錠がかかっている。）           │
│ ├ パン屋             │                                        │
│ ├ 井戸端             │                                        │
│ ├ 村はずれ ◀ 現在地   │                                        │
│ │ ├ 👤 看板          │                                        │
│ │ ├ 🔒 立入禁止       │                                        │
│ │ └ 柵の裏           │                                        │
│ └ ？？？             │ ┌────────────────────────────────────┐ │
│                      │ │ cd  場所へ移動する                    │ │
│──────────────────────│ │ cat 話しかける・調べる                │ │
│ 🎯 目的              │ └────────────────────────────────────┘ │
│ 村はずれを調べよう     │  ユウ@チルダ村:~/村はずれ$ c▌            │
│                      │  [📖 コマンド手帳] [💡ヒント]              │
└──────────────────────┴────────────────────────────────────────┘
       左: マップ＋目的                      右: ターミナル（入力候補つき）
```

- 左の **マップ**（フォルダ構成）がこの世界の地図。右が **ターミナル**
- 左下に **🎯 目的**（今やること）を常に表示し、未経験者が迷わないようにする
- 章ごとにテーマ色を変える（森＝緑、沼＝紫、坑道＝赤茶、書庫＝セピア…）
- スマホではマップを引き出し式（ボタンで開閉）にして、ターミナルを全画面にする

### 2.2 マップの仕様

場所の状態は次の6つ。

| 状態 | 表示 | cd | どうなったらこの状態になるか |
|---|---|---|---|
| 未発見 | 表示しない | できる※ | 初期状態。隠しフォルダ（`.`始まり）はずっとここ |
| 気配 | `？？？` | できない | ストーリー上「この先に何かある」と分かった |
| 判明 | 名前（薄い色） | できる | 物語で行けるようになった／`ls` で見た |
| 訪問済み | 名前（通常色） | できる | 一度 `cd` で入った |
| 施錠 | 🔒＋名前 | できない | `Permission denied` を受けた |
| 現在地 | ◀ 現在地・強調 | ― | 今いる場所 |

※ 未発見でも名前が分かれば `cd` で入れる。**`ls -a` で見つけた隠し場所はマップに後から現れる**ので、「自分で見つけた」感覚になる。

- **マップには、`ls`（`ls 場所`・`find`）で見たものと、通った場所だけを出す**。`cd` で入っただけでは、中の場所は載らない（本物の Linux に地図はなく、見渡すのは `ls`）
- **マップにはフォルダ（場所）だけを出す**。ただし現在地の中身は、人物👤・もの📜・プロセス⚙のアイコンつきで展開して見せる
- 異変のあとは、文字化けした村人に ⚠ を付けて「村が壊れた」ことを目で分かるようにする
- マップの場所をクリックすると、入力欄に `cd 〜` が **入力されるだけ**（実行はしない）。Enterを押すのはプレイヤー自身、という形で「コマンドを打つ」体験は残す
- 物見の塔（第7章）に登ると、残りの章の `？？？` が一斉に名前に変わる演出を入れる

📝 **決めること**: マップのクリックで入力するだけにするか、そのまま実行もするか（おすすめ: 入力だけ）

### 2.3 コマンド入力の補助

キーボードで打つのが大変な人のために、入力を3段構えで補助する。

**① 入力候補（サジェスト）**
- `c` と打つと、**覚えたコマンドのうち `c` で始まるもの**（`cd` `cat` …）が説明つきで入力欄の上に出る
- `cd ` とスペースまで打つと、次は **引数の候補**（`cd` なら行ける場所、`cat` なら人やもの、`kill` ならプロセス）が出る
  → **日本語入力（IME）への切り替えなしで村人の名前を入れられる**。未経験者にとってはここが一番の助けになる
- 操作: ↑↓で選択、Tab で確定、Enter で実行。候補が出ていないときの ↑↓ は、これまでの履歴を呼び出す
- まだ覚えていないコマンドは候補に出さない（`kill` は石碑を読んでから、など）
- 場所・人・ものの候補は、地図に出ているもの（`ls`・`ls 場所`・`find` で見つけたものと、通った場所）だけ。見渡していないものの名前は明かさない

**② 📖 コマンド手帳（ボタン）**
- 今までに覚えたコマンドの一覧。クリックすると入力欄にそのコマンドが入る
- 各コマンドのページには次の4つを載せる（→ 4章のガイドを兼ねる）
  - できること（物語の言葉で）／書き方／使用例／**本物のLinuxでは**（実際の使い道）
- 新しいコマンドを覚えた瞬間に「📖 手帳に `find` が追加された！」と演出を入れる

**③ 最近使ったコマンド**
- 手帳の中にタブで、これまでの履歴を並べる。クリックで再入力

📝 **決めること**: 慣れた人向けにサジェストをOFFにできる設定を入れるか（おすすめ: 入れる。Linux経験者の先生にも遊んでもらいやすい）

### 2.4 日本語の名前と入力

村人やものの名前は日本語なので、キーボードだけで遊ぶと IME の切り替えが負担になる。これは①の引数サジェストと Tab 補完で解決する。あわせて、全角で打った `ｌｓ` もそのまま通るようにする（実装済み）。

## 3. セーブとアカウント

### 3.1 方式

| | ゲスト | ログイン |
|---|---|---|
| 始め方 | URLを開くだけ | 「ログイン」ボタン（Googleアカウント） |
| 保存先 | ブラウザ（localStorage） | クラウド（Firebase Firestore） |
| 別の端末で続き | できない | できる |

- **最初はゲストで遊べるようにする**（リンクを開いてすぐ遊べることを優先）。途中でログインすると、ゲストの進行データがそのままアカウントに引き継がれる
- 両方にデータがあるときは「どちらのデータで続けるか」を、章と日時を並べて選ばせる
- 保存タイミング: コマンドを1回実行するたびに自動保存
- **章のチェックポイント**: 各章の開始時点を保存しておき、タイトルの「章を選ぶ」から、着いたことのある章の最初からやり直せる（詰んだとき・もう一度遊びたいとき用）。開発中は `?dev` をつけて開くと、全部の章を選べる

### 3.2 技術

- **Firebase Authentication（Googleログイン）＋ Cloud Firestore**。無料枠（Sparkプラン）で足りる。GitHub Pages のような静的サイトからそのまま使える
- データ: `saves/{ユーザーID}` に `{ name, flags, cwd, history, chapter, updatedAt }` を保存する
- セキュリティルールで「自分のセーブだけ読み書きできる」ように制限する
- 保存する個人情報は Firebase のユーザーIDだけ。メールアドレスなどはゲーム側に保存しない

📝 **決めること**
- ログイン方法は Google だけでよいか（学校のアカウントで Google ログインが使えるかも確認）
- セーブスロットは1つでよいか

## 4. 操作ガイド（未経験者向け）

「説明を読ませる」のではなく「遊んでいるうちに覚える」を基本にする。

1. **はじめての人向け案内（初回だけ）**: 画面の3か所（マップ・ターミナル・手帳）を順に指して説明する。3ステップで、スキップ可
2. **第0章＝チュートリアル**: 🎯目的が1手ずつ案内する
   - 例: 「`ls` と打って村を見渡そう」→「`cd パン屋` でパン屋に行こう」→「`cat` でナノに話しかけよう」→「`cd ..` で戻ろう」
   - Tab 補完・サジェスト・手帳の使い方もこの中で1回ずつ体験させる
3. **ヒント3段階**（`hint` コマンド／💡ボタン）。第1章からは案内役コダマの声で出す
   - 1回目: 方向性（「隠れているものがあるかも」）
   - 2回目: 使うコマンド（「`ls -a` を使ってみよう」）
   - 3回目: 答え（「`cd 柵の裏` → `ls -a`」）
4. **やさしいエラー**
   - 打ち間違い: `sl` → 「もしかして `ls`？」
   - スペースの付け忘れ: `cd村はずれ` → 「`cd` と場所の間にスペースが必要だよ」
   - 知らないコマンド: 「そのコマンドはまだ知らない」（手帳に誘導）
5. **クリア後のおまけ**: 「本物のLinuxで試してみよう」ページ。ゲームで覚えたコマンドを、実際のLinux環境（WSLなど）で試す手順をまとめる
6. **前の章のコマンドを、あとの章でも使う（おさらい）**: 覚えたコマンドを、覚えた章でしか使わないと忘れてしまう。
   各章の本筋に、前の章で覚えたコマンドを **2つ以上** 入れる（寄り道も入れて3〜4つ）。できれば2章以上前のものを選び、
   物語の中で必要になる場面にする（「探しものは `find`」「崖の向こうへは `ln -s`」など）。思い出させるのは、名前を出さずに
   「森で覚えた言葉があったろう」のように、その章の出来事で呼びかける
7. **少しずつ難しくする（第5章から）**: 物語の中のヒントを控えめにする。新しいコマンドは、登場人物が書き方まで教える。
   おさらいのコマンドは、物語では「何をしたいか」と思い出すきっかけだけ（「見えないものを探すなら……`find` だ！」のように、名前まではよいが、
   `-name "*.tar.gz"` のような書き方は言わない）。具体的な書き方は💡ヒントの3段目で出す。第4章までは、これまでどおり手厚く

### 4.0 おさらいの表

どの章で、前の章のどのコマンドを使うか（本筋のもの。`ls`・`cd`・`cat` は毎章使うので省く）。章を作るときは、ここに足す。

| 章 | 覚える | おさらい（前の章のコマンド） |
|---|---|---|
| 0 チルダ村 | `ls` `cd` `cat` `pwd` `ls -a` `ls 場所` `kill` | ― |
| 1 迷いの森 | `find` | `ls -a`（隠れたコダマ）、`pwd`、`cd -` |
| 2 もつれ沼 | `ls -l` `file` `ln -s` `unlink` | `find`（向こう岸・沈んだ祠を探す） |
| 3 ムラガレ | `chmod` `groups` `write` | `ls -l`（鍵の読み方）、`find`（物置の棚から薬草を探す） |
| 4 市場町イチバ | `mkdir` `mv` `cp` `cp -r` | `find`（書写屋の棚から地図の巻物を探す）、`ls -l`（金庫の鍵） |
| 5 廃墟山道 | `tar -tzf` `tar -xzf` `tar -czf` | `find`（崖の向こうの祠の住所を探す）、`ln -s`（祠へ渡る）、`mv`（紙の束に名札をつける・かばんへ）、寄り道で `ls -a`（隠れた包み） |
| 6 坑道アナグラ | `ps` `fg` `bg` `kill 番号` `chgrp` | `write`（裏のノーハップに声を届ける）、`mkdir`・`chmod`（隠れ場。組の者だけ入れる・のぞける）、`find`（出口の古い竪坑） |
| 7 物見の塔 | `date` `echo` `>` `>>` `crontab` `crontab -l` | `cp`（書き直す前に、予定表の写し `予定表.bak` をとる）、`ls -l`・`chmod`（予定表の鍵を確かめて、自分に書く鍵を開ける）、`cd` の住所（扉の中から `/etc/予定表` に書く） |
| 9 賢者の庵 | `sudo` `systemctl start` `systemctl status` | 総復習: `find`（三本の鍵）、`chmod`（錆びた箱）、`tar -xzf`（巻物・設計図）、`ls -l`・`unlink`（惑わしの札）、`cp`（`sudo cp` で設計図を抜け穴へ）、`ls -a`・`cd ~` |
| 8 記憶の書庫 | `grep` `diff` `history` `\|` | `*`（`*.log` でまとめて探す。第1章）、`ls -a`（隠された古い版の記録。第0章）、`groups`（書庫番の組に入る。第3章）、`ls 場所`（`ls ~/かばん` で設計図を確かめる。第0・4章）、`file`・`ls -l`（『守り人の原本』の札は、作成者スドウの住まい `/root` を指す。第2章） |

これで、覚えたコマンドはすべて、あとの章でおさらいしている（第9章の三の試練で `unlink`）

### 4.1 用語のたとえ

専門用語は、はじめて出てきたときに、登場人物がこの世界の例えで軽く触れる。意味をそのまま説明するのではなく「この世界では、こういうこと」と伝える。同じ用語は、章をまたいで同じ例えを使う。

| 用語 | この世界での例え | はじめて出る場面 |
|---|---|---|
| ファイル・フォルダ（ディレクトリ） | 人や物・場所 | 第0章のはじめのナレーション |
| ディレクトリの入れ子 | 場所の中に場所がある（部屋は家の中、家は村の中）。地図で一段右にずれるのが「中にある」しるし | 第0章 兄バッシュの手本 |
| 相対パス（名前だけ） | 名前だけで届くのは、いまいる場所の中にあるもの（`ls` で見えるもの）だけ | 第0章 兄バッシュの手本・名前だけで届かなかったとき |
| `..` | ひとつ外へ出る（部屋 → 家 → 村） | 第0章 兄バッシュの手本 |
| `/`（道のりをつなぐ） | 「の中の」。`../パン屋` は「ひとつ外の中の、パン屋」 | 第0章 兄バッシュの手本 |
| 入力候補 | ゲームだけの助け。兄が「本当のLinuxには、候補がこんなふうに出てくる機能はない」とメタに触れる | 第0章 兄（パン屋） |
| パス・`pwd` | **住所**。`/` は「の中の」と読む。いちばん左の `/` は世界そのもの | 第0章 ナノ（`pwd`） |
| 道のりを続けて書く（`きみの家/リビング`） | 「きみの家の中の、リビング」と続けて言えば一度で着く | 第0章 ナノ（帰り道） |
| `~` | ふるさとのチルダ村の短い呼び名（読みは「チルダ」）。村の中なら `cd ~` でいつでも戻れ、`~/…` は「チルダ村から数えた住所」。地図のチルダ村の右の `~` を照らして説明 | 第0章 兄（パンを届けたとき。`..` に慣れてから） |
| `find .` と `find /usr` | `.` は「ここ」。`find .` は「ここから下」だけ、`find /usr` は「森の入口から下ぜんぶ」 | 第1章 コダマ（鈴を返したとき。切り株の根っこに隠した首飾りを `find .` で探させる） |
| `/tmp` | 毎朝、売れ残りが片づけられる市場。だれでも店を広げられる | 第4章 掲示板 |
| `mkdir` | 新しい場所をつくる。囲いを立てて、場所をひとつ増やす | 第4章 アプト |
| `mv` | 物を運ぶ。運んだ物は、元の場所からなくなる | 第4章 アプト |
| `mv`（名前を変える） | 同じ場所のまま、札を掛けかえる | 第4章 リネ |
| `cp` | 写しをとる。元の物は、そのまま残る | 第4章 ディディ爺 |
| `cp -r` | 場所ごと、中身を奥の奥まで写す | 第4章 ディディ爺 |
| かばん | ふるさと（`~`）の中に作る、きみだけのかばん。旅先に置くとなくすので、ふるさとに作る。`mkdir ~/かばん` で作り、どこからでも住所の `~/かばん` で届く（本物と同じ。入力候補にだけ、いつも出す） | 第4章 アプト・コダマ |
| `.tar.gz`（`tar`） | 荷をぎゅっと縛って、小さくまとめた包み。`-t` は中をのぞく、`-x` はほどく、`-c` はまとめる。`z` は縛った縄、`f` のうしろに包みの名 | 第5章 スドウの書き置き・コダマ・箱の添え書き |
| プロセス・`ps` | 目には見えないが、坑道で動いている者たち。`ps` は点呼（名と番号札を呼び上げる） | 第6章 点呼板 |
| PID | 番号札。同じ名でも、番号はひとりにひとつ。`kill` は番号で唱える | 第6章 点呼板・ノーハップ |
| `fg`・`bg` | 裏で動いている者を、表（目の前）に呼ぶ／裏に戻す。裏で動くこと自体は、悪いことではない | 第6章 ノーハップ |
| `chgrp` | 場所の組（家族）を変える。組の者だけが「家族」の鍵で入れる | 第6章 ノーハップ |
| 孤児プロセス | 親を失った子。本物では、守り人（PID 1）が引き取る | 第6章 ミナシゴ |
| `ls 場所` | 入る前に、のぞく | 第0章 ピコ（第1章 フクロウが森でもう一度） |
| 絶対パス（`/` から） | 世界から数えた住所。`~` は本当は `/home/チルダ村`。ほかのステージは、地図の右の `/usr` などを打てば、そのステージのいちばん大きな場所へ行ける | 第0章 チョウン爺（旅立ち。地図の `/usr` を照らす） |
| リンク（シンボリックリンク） | 遠くの場所や物を、ここから指さしている道しるべ・名札 | 第2章 ツナギ（ls -l）、コダマ（file） |
| リンク切れ（broken） | 指さした先が消えて、道しるべだけが残ったもの | 第2章 コダマ（渡り道A） |
| `ln -s` の `-s` | symbolic の s。名札を自分の手で立てること | 第2章 ツナギ |
| `unlink` | 繋がりを解く言葉。札を抜くだけで、指さした先は壊れない | 第2章 ツナギ |
| Permission denied | 「ここに○○してはならぬ」と言われる、許しがない | 第2章 置けない場所で ln（第3章で詳しく） |
| パーミッション（`rwxr-x---`） | 家の扉にかかった鍵のかけ方 | 第3章 グロウプ婆 |
| r / w / x | 窓から中をのぞける／中に物を置ける／扉を開けて入れる | 第3章 グロウプ婆 |
| 3組の rwx | 左から「持ち主」「家族（同じ組の人）」「よその人」への許し | 第3章 グロウプ婆 |

## 5. 公開（GitHub Pages）

リポジトリ: https://github.com/RayOguma/Moribito

**完成までは非公開（Private）で開発し、遊べる状態になったら公開（Public）にする。**

- 無料プランでは非公開リポジトリで GitHub Pages が使えないため、非公開の間は GitHub Actions でテストとビルドだけ行う（`.github/workflows/deploy.yml`）
- 開発中は `npm run dev` で手元のブラウザで遊ぶ
- 公開するときの手順
  1. Settings → General → Danger Zone → Change repository visibility → Public
  2. Settings → Pages → Source を「GitHub Actions」にする
  3. Actions タブから Deploy を実行（または何か push する）
  4. `https://rayoguma.github.io/Moribito/` で遊べることを確かめ、URL や QR コードを配る
- Firebase（ログイン機能）を入れたら、承認済みドメインに `rayoguma.github.io` を追加する

📝 公開前に友だちにテストプレイしてもらいたくなったら、リポジトリを非公開のまま遊んでもらう方法（別の無料サービスで限定公開する、など）を考える
