## 5. 作るもの（システム）

- `mkdir 名前`: 書きこめる（`w`）場所の中に、新しい場所を作る。作った場所の持ち主は「きみ」
- `mv 元 先`: 運ぶ（先が場所なら、その中へ）／名前を変える（先が今ない名前なら）。元の場所と先の場所の両方に `w` がいる
- `cp 元 先`、`cp -r 元 先`: 写しをとる。場所を写すには `-r` がいる（本物と同じく「-r がないので、場所は写せない」と出す）
- 動かせない物: 人は運べない・写せない（「アプトは、荷物じゃない」）。シナリオの物はふつう動かせず、運ばせたい物だけ `movable: true` にする。プレイヤーが作った・写した物は運べる
- 写した物は、中身（せりふ）だけ写す。フラグ・手帳・「!」などの物語の仕掛けは写さない
- プレイヤーが作った・運んだ・写した物は、セーブに手順として残し、読みこむときに同じ順でやり直す（`links` と同じ考え方）
- イベントの条件に「この場所に、これがある／ない」（`exists` / `missing`）と、「コマンドに書いた名前がこの物を指している」（`target`）を足す（例: 果物屋に木箱がある → 運んだ）
- 会話で棚に置かれた物（通行証）は、`ls` しなくても地図に載せる（`variants` の `reveal`）
- 章の `clear` にも手順を書けるようにする（「章を選ぶ」で第5章から始めるとき、かばんができているように）
- 市場の枠（天幕のタイル）、アプト・ディディ爺・リネ・ピップの立ち絵、露店のアイコン
- 第3章の終わりに `/tmp` へ移る（`moveTo`）

## 6. 決まったこと

- かばんの仕組みを入れる。かばんは `mkdir ~/かばん` で作る（ふるさとにつながった、きみだけのかばん）。第5章の `tar`、第9章で使う
- かばんの届き方は本物と同じ。どこからでも、住所の `~/かばん` で届く（名前だけの `かばん` では届かない。`cd かばん` もできない）。ゲームだけの特別なしくみにはしない
- ただし入力候補には、仲間（コダマ）と同じく、どこにいても「かばん」を出す。選ぶと `~/かばん/` が入る。地図の下に「🎒 かばん ~/かばん」の欄を出し、いつでも中身が見えるようにする（中の物をクリックすると `cat ~/かばん/…` が入る）
- かばんを作ったとき、枠と吹き出しで使い方を紹介する（住所は `~/かばん`、候補にもいつも出る）
- 通行証は、第5章の山道の入口の関所で使う（📝 第5章で、通行証を見せないと通れない場面を作る）
- 町の雰囲気は、にぎやか＋小さな異変（売れ残りが片づかない）
- `cp` と `cp -r` の両方を教える

- 人物の名前: アプト（`apt`）、ディディ爺（`dd`＝写す道具）、リネ（rename）、ピップ（`pip`＝もうひとつの荷物屋）
- 物語で頼まれていない `mkdir` / `mv` / `cp` はできない（「いまは、○○を動かす用事はない」）。名前は合っているのに場所がちがうと、頼んだ人が正しい場所を教える（例: アプト「かばんは、あんたのふるさと（`~`）の中に作るんだ」）。オートセーブなので、世界に意味のない場所や物を増やさないため
- `..` のあとに `/果物屋` と続ける書き方は、アプトがはじめて説明する（「ひとつ外に出た、その中の果物屋」「最後の `/` は『その中へ』」）
- かばんの欄は、はじめは閉じておく（物が増えても地図が狭くならないように）。入力候補では、仲間とかばんは、いまいる場所の物のあとに出す
- 第1章の首飾りは、かばんに入れない（主人公が身につけたまま。後の章で「守ってくれる」場面に使う）
- スドウの覚え書き（3枚）: 各地の支え（市場の片づけ番も）は、みな守り人から枝分かれした子。根が枯れれば枝も枯れる（守り人＝PID 1。主人公の kill が各地の異変の原因だと匂わせる。第6章のゾンビ・孤児、第7章で市場の異変が片づく、第9章で支えが戻る）／どんな扉でも開ける鍵束を、ひとりで持つべきではない（root、第9章へ）／守り人の設計図は山道に預けた（第5章の設計図へ）
